# 🚧 예정 통지: Storage Tiering (5-Tier) 기반 쿼리 옵티마이저 고도화

해당 문서는 DBX 프로젝트의 **5-Tier 하이브리드 스토리지 엔진(Delta -> Cache -> WOS -> Index -> ROS)** 아키텍처와 **분산 쿼리 엔진**을 결합하기 위해 예정된 구조적 고도화 및 최적화(Phase) 진행 명세서입니다.

## [Added] 티어 인지 파티션 푸루닝 (Tier-Aware Partition Pruning)
- 옵티마이저가 쿼리 분석 단계에서 Storage 레이어의 메타데이터를 직접 참조하여 쿼리의 스캔 영역을 최소화하는 규칙이 추가됩니다.
- 쿼리 Filter 특성상 최근 데이터만 필요한 경우, `TableScanOperator`가 내부적으로 `Cold Tier(ROS)` 스캔을 건너뛰고 `Memory / Warm Tier`만 타겟팅하도록 Execution DAG를 깎아냅니다.

## [Added] Storage Locality (데이터 지역성) 최적화 스케줄링
- 코디네이터(`DistributedExecutor`)가 워커들에게 Fragment를 배분(Dispatch)할 때, 요청된 테이블의 **Hot Data(Cache/WOS)**를 보유하고 있는 특정 워커에게 쿼리 할당 가중치를 부여합니다.
- `Cache` 히트율 및 `NodeRegistry`의 데이터 배치 현황을 반영하는 스케줄링 라우터가 엔진에 내장됩니다.

## [Changed] 물리 연산자 하이브리드 머지 파이프라인
- 기존의 단순 `TableScanOperator`를 다중 계층 읽기가 지원되도록 확장합니다.
- 메모리의 `Delta/WOS`는 동기적으로(빠르게) 읽어 들이고, 디스크의 `ROS`는 비동기 스트림으로 읽어들여 쿼리 파이프라인 내에서 끊김 없이 통합(Union)하는 Non-blocking 스트림 파이프라인 교체가 예정되어 있습니다.

## [Performance] LifecycleWorker 시스템 자원 분리
- 핫/콜드 데이터 마이그레이션(배경 병합 작업)을 담당하는 `LifecycleWorker` 시스템과 쿼리 워커 간의 CPU 자원 및 메모리 풀을 격리하여, 대규모 데이터 병합 중에도 쿼리 속도의 지연 간섭(Latency spike)을 막아냅니다.
