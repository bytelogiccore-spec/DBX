# 🚧 예정 통지: 내결함성(Fault Tolerance) 및 메모리 방어 (Spill-to-Disk)

해당 문서는 DBX 쿼리 엔진이 분산 노드 장애 상황이나 초거대 데이터셋(OOM 유발) 환경에서도 쿼리 파이프라인을 끊김 없이 안정적으로 연산해낼 수 있도록 하는 아키텍처 고도화 예정 명세서입니다.

## [Added] 분산 쿼리 내결함성 (Fault Tolerance & Retry)
- **장애 감지 (Failure Detection):** 코디네이터(`DistributedExecutor`)가 QUIC 연결 상태 및 지속 하트비트를 통해 각 워커의 건전성(Health) 상태를 실시간 모니터링합니다.
- **Fragment 재스케줄링:** 쿼리 실행 중 특정 워커가 Panic, Timeout 등으로 다운되었을 때 전체 쿼리를 취소하는 대신, 해당 워커에 부여했던 `ExecuteFragment`를 타 유휴 노드(Back-up Worker)로 재라우팅(Retry)하여 부분 파이프라인만 재수행하는 Resilience를 갖춥니다.

## [Added] Spill-to-Disk 메모리 방어 체계
- **Grace Hash Join & Aggregate:** `HashJoin` 밎 `HashAggregate` 등 빌드 과정에서 메모리를 대량으로 소비하는 Blocking Operator에 메모리 풀 프로파일러를 부착합니다.
- 정의된 RAM 할당 임계치를 넘길 경우 데이터를 전부 메모리에 올리지 않고, 로컬 임시 스토리지(Temp Directory) 단위로 파티션 **Spill(디스크 유출)** 한 뒤 스트리밍 기반으로 병합해 나가는 OOM 완벽 차단 구조를 도입합니다.

## [Performance] 워커 리소스-인식 배압 (Resource-Aware Backpressure)
- 현재 고정된 버퍼(Bounded Channel)로 제어 중인 `GridExchange` 및 `ShuffleWriter`의 송수신 큐 한도를 각 머신의 가용 I/O 대역폭과 메모리 여유분에 따라 동적 조절합니다.
- 쏟아지는 네트워크 `ExchangeData`로 인해 워커가 쓰러지지 않도록 수신 백프레셔(Backpressure)를 더욱 촘촘하게 제어합니다.
